# 小程序账户与支持内容接口化设计

## 状态

- 日期：2026-08-24
- 设计状态：已在对话中逐节确认
- 涉及应用：Miniapp、Server、Admin、shared-types

## 背景

Miniapp 的页面与视觉结构已经基本完成，但用户、个人资料和支持内容仍主要使用静态数据。Server 已具备微信登录、刷新令牌、阿里云短信验证码、腾讯 COS 公共头像存储，以及带草稿、发布和历史版本的 Website Content 内容管理能力。

现有微信登录要求首次用户先通过微信手机号能力绑定手机，这与个人主体小程序当前无法使用该能力的条件冲突。退出登录虽然已有服务端接口，但 Miniapp 没有会话管理；账户注销尚未实现。隐私协议、帮助中心和客服页面也仍为写死内容。

本设计优先扩展现有能力，不增加第二套认证、短信、对象存储或内容管理系统。

## 目标

- Miniapp 启动后静默登录，首次微信用户自动创建账户并获得随机昵称和稳定随机默认头像。
- 未完善手机号的用户可以浏览公开内容，但发布、接单、评论、收藏、聊天等真实写操作必须被阻止。
- 个人信息详情与编辑页读取真实数据，并支持微信官方头像、昵称填写能力。
- 使用阿里云短信验证用户自行填写的手机号。
- 完成当前设备退出登录，以及带订单检查和身份确认的账户注销。
- 在“我的”页面增加隐私协议入口。
- 隐私协议、帮助中心和客服信息均通过现有 Admin 内容发布流程配置。
- 保持加载、禁用、可点击、错误和重试状态一致，不让不可用功能表现得像可用功能。

## 非目标

- 不实现微信手机号快捷获取能力。
- 不实现已绑定手机号的自助更换；首版只支持未绑定用户完成首次绑定。
- 不实现注销冷静期、自助恢复或重新注册已注销微信身份。
- 不物理删除历史订单和审计记录，也不在本期定义法定数据保留期限。
- 不启用目前仍为静态占位的业务能力，不为它们补写假接口。
- 不新建 FAQ 专用 CMS、全文检索服务或第二套 Miniapp 内容后台。
- 不增加新的客户端状态管理依赖。

## 方案选择

采用“复用并扩展现有能力”：

- 微信认证继续使用现有 `WechatAuthService`、`WechatApiClient` 和令牌体系。
- 手机验证继续使用现有 `VerificationCodeService` 和阿里云短信发送器，但验证码必须按用途隔离。
- 用户头像上传复用现有公共头像存储与文件校验。
- 隐私、帮助和客服内容继续使用 Website Content 的草稿、发布、历史版本、校验和缓存。

未采用独立 Miniapp 用户中心模块和独立 CMS，因为它们会重复身份、短信、权限、存储和发布逻辑。未采用纯前端门禁，因为客户端状态可以被绕过，不能保护服务端写操作。

## 一、账户状态模型

资料是否完善不新增数据库字段，直接由“已绑定并验证手机号”推导：

```text
匿名浏览
  └─ 静默或主动微信登录 ─> 已登录、资料未完善
                              ├─ 验证并绑定手机号 ─> 已登录、资料已完善
                              ├─ 主动退出 ─> 匿名浏览且暂停自动登录
                              └─ 注销账户 ─> 账户停用、所有会话失效

已登录、资料已完善
  ├─ 退出登录 ─> 匿名浏览且暂停自动登录
  └─ 注销账户 ─> 账户停用、所有会话失效
```

状态定义：

- `anonymous`：没有有效会话，仍可浏览公开页面。
- `authenticated_incomplete`：微信身份有效，但 `phone` 为空。
- `authenticated_complete`：微信身份有效，且 `phone` 已通过短信验证。
- `inactive`：账户已注销或被停用，任何访问令牌均不可继续使用。

`profileComplete` 由 Server 返回，Miniapp 不自行猜测。Server 仍是写操作门禁的最终判定方。

## 二、数据与共享契约

### Prisma

- `User.phone` 从必填改为可空并继续保持唯一约束。PostgreSQL 允许多条 `NULL`，已绑定手机号仍不能重复。
- `UserProfile` 增加可空 `bio` 字段。
- 复用现有 `UserProfile.address` 存储个人信息页的“所在地区”。
- 不新增 `profileComplete`、默认头像编号或注销记录字段。

数据库迁移必须由 Prisma CLI 生成，不手写迁移文件。现有已绑定手机号用户不需要数据回填。

### Miniapp 用户契约

Miniapp 会话与个人资料响应至少包含：

- `id`
- `nickname`
- `avatar`
- `phoneMasked`
- `profileComplete`
- `userType`
- `region`
- `bio`

Miniapp 响应和 JWT 不携带完整手机号。Admin 已有的管理员会话契约保持完整手机号，因为后台登录仍以手机号为凭据。

### 默认资料

- 首次创建用户时使用 Node.js `crypto.randomInt` 生成 `宠友` 加六位数字的昵称；昵称允许重复，不为展示名称增加唯一约束。
- `avatar` 为空时，Miniapp 按用户 ID 稳定映射到现有宠物默认头像池。该结果对同一用户保持不变，避免每次刷新更换头像。
- 用户上传自定义头像后，以 Server 返回的公共 URL 为准。

## 三、静默登录与会话

### 启动流程

1. Miniapp 读取本地 `manualLogout` 标记。
2. 若用户刚主动退出，则保持匿名，不自动调用微信登录。
3. 否则优先使用本地刷新令牌恢复会话。
4. 刷新令牌缺失或失效时调用 `uni.login`，把临时登录码发送给现有 `/auth/wechat/login`。
5. 已存在的活动账户直接签发会话；首次微信身份在事务内自动创建用户并签发会话。
6. 网络失败或微信登录失败时保持匿名并允许浏览；受限操作会再次引导登录。

首次用户不再返回 `phone_required` 和临时绑定令牌。现有微信手机号绑定接口可以保留兼容性，但 Miniapp 新流程不再调用。

### 客户端会话

- 增加一个轻量请求模块和一个 Vue 响应式会话模块，统一持有访问令牌、刷新令牌、用户信息和启动状态。
- 请求收到 401 时最多自动刷新一次，并重放原请求一次；刷新失败后清理会话，避免刷新循环。
- 会话数据使用 `uni` 存储接口，不引入 Pinia 或其他状态库。
- 受限动作在等待登录、刷新或跳转期间必须锁定重复点击。

### 主动退出

- 调用现有 `/auth/wechat/logout` 撤销当前刷新会话。
- 无论服务端调用成功还是因断网失败，本机都清理令牌和用户资料，保证用户能够离线退出本机。
- 写入 `manualLogout`，后续启动保持匿名；用户点击登录或受限操作并确认登录后再清除该标记。
- 普通退出不改变账户状态，也不强制退出其他设备。已签发的短期访问令牌按现有 TTL 自然过期。

## 四、个人信息与微信官方资料能力

### 页面字段

个人信息详情页展示真实的：

- 头像
- 昵称
- 脱敏手机号或“未绑定”
- 所在地区
- 个人简介

静态信用值不继续作为真实个人资料展示；有真实信用数据时再单独接入。其他不属于本期的订单、优惠券等统计仍由各自后续接口任务处理。

编辑页支持：

- 微信端头像：`button open-type="chooseAvatar"`
- 微信端昵称：`input type="nickname"`
- 所在地区
- 个人简介
- 未绑定手机号的短信验证入口

微信头像选择返回临时文件路径，Miniapp 必须上传到 Server 后才能持久化。微信提供的昵称和头像属于用户输入，不作为实名或可信身份凭据。

H5/App 构建使用普通文本输入与 `uni.chooseImage`，不伪造微信资料读取能力。

### 保存边界

- 昵称去除首尾空白后必须为 1 至 24 个字符，并拒绝控制字符。
- 所在地区与个人简介执行长度限制和控制字符校验。
- 文本资料通过 `PATCH /users/me` 保存。
- 头像通过独立 multipart 接口上传，成功后立即更新当前资料；文本保存失败不回滚已经成功的头像上传。
- 头像继续使用现有文件头识别、类型和大小限制；对象键使用 Miniapp 用户头像目录，不能删除其他用户或后台管理员的对象。

## 五、手机号短信验证

### 发送与绑定

- 发送短信接口必须要求有效的 Miniapp 微信会话。
- 用户输入手机号后，Server 使用现有手机号格式校验、发送冷却、每小时上限和阿里云短信发送器。
- 除按手机号限流外，再按当前用户限制发送次数，降低单个微信账户批量发送到不同号码的风险。
- 绑定接口同时提交手机号和验证码；验证码成功消费后，Server 在事务中确认手机号未被其他账户占用，再写入 `User.phone`。
- 若手机号已存在，返回稳定冲突错误，不自动合并两个账户。
- 成功后响应最新用户资料，`profileComplete` 立即变为 `true`。

### 验证码用途隔离

验证码 Redis key 和校验必须包含服务端确定的用途，至少区分：

- `admin_login`
- `miniapp_bind_phone`
- `miniapp_cancel_account`

客户端不能通过传入任意用途改变校验范围。一个流程发送的验证码不能在另一个流程消费。

## 六、资料完善门禁

### Miniapp

所有已经具备真实点击行为的受限入口调用同一个门禁函数：

1. 没有会话时请求用户确认并执行微信登录。
2. 已登录但资料未完善时跳转个人信息编辑页，并携带安全的站内返回路径。
3. 资料已完善时继续原操作。

首批受限范围为发布悬赏、接单、评论、收藏、关注和聊天发送；只有已经存在真实业务入口的动作才接入。仍处于静态占位的按钮继续保持视觉、可访问性属性和行为上的不可用状态。

### Server

- 对现有对应写接口增加统一的资料完善检查。
- 未完善时返回 HTTP 403 和稳定错误码 `PROFILE_INCOMPLETE`。
- 公开读取接口、帮助、隐私、客服和浏览类查询不要求资料完善。
- 认证与资料完善是两个判断：未登录返回 401，已登录但资料未完善返回 403。

## 七、账户注销

### 前置条件

- 注销入口先展示不可恢复、会话失效和历史记录保留说明，并要求二次确认。
- Server 检查用户作为发布方或服务方是否存在进行中订单；存在时阻止注销并返回可理解的错误。
- 已绑定手机号的账户必须先向当前手机号发送 `miniapp_cancel_account` 用途验证码，并在注销请求中消费。
- 未绑定手机号的初始账户使用当前有效微信会话和二次确认完成注销，不额外要求手机号。

### 执行结果

- 在事务中重新检查账户状态和进行中订单。
- 将 `User.status` 设为 `inactive`，并递增 `sessionVersion`。
- 现有 JWT 校验会因此使所有设备的访问令牌立即失效；所有刷新会话也不能再使用。
- Miniapp 清空本地会话并进入匿名状态。
- 已注销 `openid` 保留在停用账户上，微信登录不得创建第二个账户。
- 历史订单和必要审计记录保留；个人主页不再公开展示该账户。

本流程实现业务账户停用，不代表已经完成法定数据删除与保留期限评审。正式上线前仍需根据实际经营主体、业务凭证和隐私政策进行法律复核。

## 八、隐私、帮助和客服内容

### 内容管理复用

- 继续使用 Website Content 的固定模板、草稿、发布、历史版本、RBAC、校验和公开缓存。
- Miniapp 直接读取现有公开 `/website-content/:contentKey` 响应，不增加内容转发接口。
- Miniapp 只展示已发布版本；未发布的草稿不能影响线上内容。

### 隐私协议

- “我的”页面新增“隐私协议”入口和对应内容页。
- 读取现有 `PRIVACY` 内容项的 `RICH_TEXT` 区块。
- 后台配置的业务隐私协议与微信平台提供的《小程序隐私保护指引》不是同一份内容，不用 `openPrivacyContract` 替代后台内容页。

### 帮助中心

- 在共享内容键中增加 `HELP`。
- 使用多个现有 `RICH_TEXT` 区块表达帮助分类，不增加 FAQ 区块类型：区块标题为分类，小节标题为问题，段落为答案。
- 初始模板提供“账号与认证”“悬赏与订单”“服务记录”“费用与优惠”四个分类；后台可修改标题、问题和答案，也可停用不需要的分类。
- Miniapp 在内存中按问题和答案做大小写不敏感的关键词过滤，不增加搜索服务。
- 首版分类数量由固定模板限定；确有动态增删分类需求时再扩展模板能力。

### 联系客服

- 继续读取现有 `CONTACT` 的 `CONTACT_PANEL` 区块。
- `channels` 配置电话、邮箱及其他渠道；每个渠道的 `availability` 展示对应工作时间。
- `tel:` 渠道调用 `uni.makePhoneCall`。
- 邮箱在 Miniapp 中提供复制操作，不依赖不稳定的 `mailto:` 跳转。
- 其他渠道只有存在可执行且安全的动作时才显示按钮；纯说明渠道只显示文本。
- 未配置渠道不渲染，不保留写死号码、邮箱或假在线客服按钮。

### 加载与错误状态

- 页面加载时展示现有布局内的轻量加载状态。
- 空内容显示“暂未配置”，接口失败显示错误文案和重试按钮。
- 不以旧静态 fixture 冒充最新发布内容。

## 九、API 边界

| 方法  | 路径                           | 认证要求           | 用途                       |
| ----- | ------------------------------ | ------------------ | -------------------------- |
| POST  | `/auth/wechat/login`           | 无                 | 静默登录或首次自动创建账户 |
| POST  | `/auth/wechat/refresh`         | 刷新令牌           | 旋转 Miniapp 会话          |
| POST  | `/auth/wechat/logout`          | 刷新令牌           | 撤销当前刷新会话           |
| GET   | `/users/me`                    | 登录               | 读取当前个人资料           |
| PATCH | `/users/me`                    | 登录               | 更新昵称、地区和简介       |
| PUT   | `/users/me/avatar`             | 登录、multipart    | 上传并替换头像             |
| POST  | `/users/me/phone/code`         | 登录且手机号未绑定 | 发送绑定手机号验证码       |
| PUT   | `/users/me/phone`              | 登录且手机号未绑定 | 校验验证码并绑定手机号     |
| POST  | `/users/me/cancellation/code`  | 登录且手机号已绑定 | 发送注销验证码             |
| POST  | `/users/me/cancel`             | 登录               | 检查条件并注销账户         |
| GET   | `/website-content/:contentKey` | 无                 | 读取已发布支持内容         |

固定 `/users/me` 路由必须注册在现有 `/users/:id` 之前。现有公开用户详情不能继续返回手机号；若业务仍需要公开用户卡片，只返回明确的公开字段。

## 十、错误与安全

- 保留统一 API 错误 envelope，并为资料未完善、手机号冲突、验证码错误、进行中订单和账户停用提供稳定错误码。
- 手机号在 Miniapp 展示和响应中脱敏，不进入 JWT，不写入应用日志。
- 验证码继续只保存 HMAC 摘要，并保留 TTL、冷却、小时上限、失败次数和原子消费。
- 头像上传不信任扩展名或客户端 MIME，继续以文件字节检测为准。
- 内容继续拒绝任意 HTML；Miniapp 只渲染共享类型允许的纯文本结构。
- 受限按钮在加载、提交或跳转期间同步更新禁用属性、视觉和点击行为。

## 十一、测试与验收

### 约定的测试接缝

实现采用测试先行，优先覆盖以下可观察行为：

- Shared Types：Miniapp 用户、资料更新、手机验证、注销和 `HELP` 内容键契约。
- Server 微信认证：首次登录自动创建、并发唯一冲突、已有账户登录、停用账户拒绝、刷新与退出。
- Server 手机验证：用途隔离、发送限制、验证码消费、手机号唯一冲突和完成状态更新。
- Server 资料：读取脱敏资料、字段校验、头像替换与旧对象清理。
- Server 门禁：匿名 401、未完善 403、资料完善后放行。
- Server 注销：进行中订单阻止、短信验证、无手机账户注销、会话版本失效。
- 内容管理：`HELP` 模板校验、草稿不公开、发布后公开、联系渠道与隐私内容映射。
- Miniapp：启动恢复、静默登录、主动退出抑制、401 单次刷新、资料门禁返回、短信倒计时、帮助搜索和内容错误重试。
- Admin E2E：编辑并发布帮助、隐私或客服内容后，公开接口返回新版本。

### 验收场景

1. 新微信用户首次打开 Miniapp，无需手机号即可得到随机昵称和默认头像并浏览页面。
2. 未绑定手机号发布悬赏时进入资料完善页，直接调用写接口也得到 `PROFILE_INCOMPLETE`。
3. 用户通过阿里云短信绑定手机号后返回原操作，受限操作可以继续。
4. 用户可通过微信头像、昵称组件更新资料，重新启动后仍显示服务端数据。
5. 主动退出后重新打开仍为匿名；显式登录后恢复账户。
6. 有进行中订单时不能注销；无进行中订单且验证通过后，所有旧会话立即失效。
7. Admin 修改并发布隐私、帮助或客服内容后，Miniapp 展示新发布版本；草稿不影响线上。
8. 未配置电话、邮箱或其他渠道时，对应按钮不显示；配置电话后可调用系统拨号。
