# PetCare 小程序全量静态页面设计规格

**日期：** 2026-08-23

## 1. 目标

在 `apps/miniapp` 中实现原型路由表的全部正式页面与默认状态，并保留登录页。页面使用静态示例数据，完成基础页面跳转，但不接入 API、状态管理、持久化或真实业务提交。

本次交付覆盖原型中的 34 个正式路由条目，以及登录页，共 35 个页面或页面状态。`/home` 与 `/rewards` 只作为兼容入口跳转，不制作重复业务页面。

## 2. 权威来源

出现冲突时按以下顺序解释：

1. `docs/10-brand-system/PetCare-Brand-Book-v1.0.md` 与已批准品牌资产。
2. `docs/01-requirements/04-prototype-specification.md` 的路由、页面结构和文案。
3. `docs/superpowers/specs/2026-08-09-petcare-mobile-ui-design.md` 的移动端视觉基线。
4. 本规格对 UniApp 静态实现范围的约束。

现有小程序页面可作为代码结构参考，但视觉冲突时不高于上述来源。

## 3. 范围

### 3.1 页面与状态

| 批次       | 页面或状态                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 基础层     | 登录、首页、悬赏大厅、社区、消息、我的                                                                                   |
| 悬赏       | 地图模式、发布步骤 1、发布步骤 2、发布步骤 3、发布成功、悬赏详情                                                         |
| 订单照护   | 订单列表、订单详情、实时监控、聊天                                                                                       |
| 宠物与个人 | 宠物列表、新增宠物、宠物详情、编辑宠物、收藏、关注、评价、服务详情、照护者详情、店铺详情、创作者主页、个人信息、编辑信息 |
| 内容与支持 | 课堂文章详情、社区文章详情、优惠券、钱包、帮助中心、联系客服                                                             |

每个正式路由只实现一个默认静态状态。悬赏地图模式作为原型明确要求的额外状态保留。加载、空、错误、离线、无权限和深色模式不在本次范围内。

### 3.2 基础跳转

- 主 Tab 之间使用 `uni.switchTab`。
- 主 Tab 进入子页面使用 `uni.navigateTo`。
- 子页面返回使用 `uni.navigateBack`。
- 发布悬赏流程的下一步、上一步和完成按钮只负责静态页面跳转。
- 详情页使用固定页面加查询参数表达原型中的动态 ID。
- `/home` 跳转首页，`/rewards` 跳转悬赏大厅。

### 3.3 非目标

- 不请求后端接口，不新增 API 客户端。
- 不新增全局状态管理，不保存表单、筛选或登录状态。
- 不实现真实定位、地图、聊天、视频、支付、上传、拨号或客服能力。
- 不实现表单校验、提交防重、加载反馈和异常恢复流程。
- 不增加社区发布、关于、公开用户主页或系统状态等路由表之外的补充页面。

## 4. 技术架构

### 4.1 包结构

- 主包保留登录页与 5 个主 Tab，确保首屏和主导航稳定。
- 子页面按悬赏、订单照护、宠物个人、内容支持拆分为 UniApp 分包。
- 公共 SVG 和已存在的主导航资源继续放在共享静态目录。
- 只被单一业务域使用的图片资源放入对应分包，避免无条件进入主包。

### 4.2 布局组件

- 保留 `MainTabLayout`，只服务 5 个主 Tab。
- 新增一个 `SubPageLayout`，统一子页面安全区、返回导航、滚动内容区和可选固定底部操作区。
- 微信端以胶囊底部作为子页面内容起点；H5 与 App 使用平台安全区顶部。
- 子页面不显示底部 Tab，固定底部操作必须叠加底部安全区。
- 不创建配置驱动的通用页面渲染器，也不预建未出现重复需求的组件。

### 4.3 样式

- 继续使用 UniApp、Vue 3、Wot UI 和 UnoCSS。
- 页面主体采用 flex + px 流式布局，不使用 rpx。
- 常用颜色、间距、尺寸、圆角、阴影、字号和行高统一维护在 `design-tokens.ts`，通过 `uno.config.ts` 暴露语义类。
- 页面 class 只使用语义 Token，例如 `px-action`、`h-header`，禁止 `px-[16px]` 等裸任意值。
- 不新增独立 CSS 或 SCSS；只有 UnoCSS 无法表达的平台特性才允许局部内联样式。
- 最小触控区域为 44×44px，内容不得进入状态栏、微信胶囊或底部系统手势区。

### 4.4 组件复用边界

只复用已出现明确重复的结构：

- 主 Tab 布局。
- 子页面布局与返回导航。
- 已有 Wot UI 基础控件。

卡片、列表项和静态展示块先保留在业务页面内。只有同一结构被至少三个页面稳定复用时，才提取为业务组件。

## 5. 静态数据与页面行为

- 页面示例数据默认定义在当前页面的 `<script setup>` 中。
- 同一实体需要在多个页面保持一致时，才提取到对应业务域的 `fixtures.ts`。
- 路由参数缺失或无法识别时使用默认示例实体，页面不能空白或抛错。
- 筛选、分段按钮和表单字段以视觉展示为主；只有原型明确要求进入另一页面或地图状态时才产生跳转。
- 不可用控件必须同时表现为不可用并阻止点击，不允许只改变颜色。

## 6. 实现批次

### 批次 1：基础层

建立子页面布局、分包路由和统一安全区规则，复核现有登录页及 5 个主 Tab。完成后所有后续页面都只组合既定 Token 和布局。

### 批次 2：悬赏

完成列表与地图状态、发布三步、成功页和详情页，并打通首页、悬赏大厅和发布流程之间的静态跳转。

### 批次 3：订单照护

完成订单列表、订单详情、实时监控和聊天页，并打通消息页与订单链路。

### 批次 4：宠物与个人

完成宠物管理、收藏关注评价、个人资料，以及服务、照护者、店铺和创作者详情页，并打通“我的”页面入口。

### 批次 5：内容与支持

完成两类文章详情、优惠券、钱包、帮助和客服页面，并打通首页、社区与“我的”页面入口。

## 7. 验证

每个批次完成后执行：

1. 路由清单检查，确保当前批次页面已注册且能从入口访问。
2. 与安全区、路由映射相关的最小 Vitest 回归测试。
3. Miniapp `typecheck`、`lint` 和 `git diff --check`。
4. 微信小程序、H5 和 App Android 构建。
5. 在微信开发者工具和 H5 中抽查当前批次关键页面，确认无胶囊遮挡、底部遮挡、意外横向滚动、文字裁切或裸值样式。

不为纯静态文案和重复页面机械增加组件快照测试。

## 8. 验收标准

- 34 个正式路由条目和登录页均有对应静态页面或状态。
- 两个兼容入口只跳转到规范主页面，不复制内容。
- 所有设计内入口、返回按钮和流程按钮可完成基础跳转。
- 仅 5 个主 Tab 显示底部导航，所有子页面均无底部 Tab。
- 微信胶囊、状态栏和各平台底部安全区均不遮挡内容。
- 页面使用 flex + px 和 UnoCSS；常用视觉值全部来自共享 Token，无 rpx 和业务页裸值。
- 图片和图标复用批准资产，不使用 Emoji 充当结构图标。
- 微信、H5 与 App Android 构建通过，关键页面视觉检查通过。
