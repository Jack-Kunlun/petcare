# 后台错误提示、登录安全与课堂文章发布设计

## 状态

- 日期：2026-08-23
- 设计状态：已在对话中逐节确认并完成规格审阅
- 涉及应用：Admin、Server、Website、shared-types

## 背景

当前后台存在三类相互独立但会共同影响运营体验的问题：

1. Server 已返回统一的安全错误 `message`，但 Admin 大量页面仍显示写死的通用错误，或完全不展示服务端信息。
2. 短信登录已经具备短信发送冷却、短信验证码失败次数和图形验证码失败次数限制，但图形验证码常驻登录表单；密码登录没有 Redis 防爆破限制。
3. 课堂文章已有数据模型、后台只读列表和官网公开读取链路，但缺少新建、编辑、发布、下线及图文编辑能力。

本设计在保留现有统一响应、Redis、RBAC、腾讯 COS 和课堂文章模型的前提下补齐这些闭环。

## 目标

- 全后台 API 失败统一显示服务端安全 `message`。
- 全局错误提示固定显示 3 秒，同一时刻只显示一条；普通错误占用期间忽略后续普通错误，非预期会话失效类错误可以抢占。
- 短信登录默认不显示图形验证码，只在发送短信前通过弹窗完成图形验证码确认。
- 短信发送成功后，发送按钮自身显示 60 秒逐秒递减的禁用状态。
- 最终短信登录只提交手机号和短信验证码。
- 保留现有短信、短信验证码和图形验证码限制，并为密码登录增加 Redis 防爆破限制。
- 允许获授权管理员新建、编辑、发布和下线课堂文章。
- 使用 Tiptap 编辑图文正文，图片上传复用现有腾讯 COS 素材能力。
- 仅向官网公开已发布文章，并安全渲染服务端清洗后的富文本。

## 非目标

- 不增加文章审核流、定时发布、版本历史、协同编辑或外部 CMS。
- 不允许直接编辑已发布文章；必须先下线，避免绕过显式发布动作。
- 不增加 IP 限流。当前 Server 未建立可信代理解析边界，直接按 IP 限流可能把反向代理后的用户合并为同一来源。
- 不新增第二套对象存储、素材表或媒体上传协议。
- 不迁移现有 `ClassroomArticle.content` 数据库列。

## 方案选择

课堂文章采用 Tiptap、StarterKit（含 Link）和 Image 扩展。编辑器输出 HTML，Server 通过严格白名单清洗后，加内部 v1 格式前缀写入现有 `content` 字段。

未采用 Tiptap JSON 持久化，因为它还需要新增共享文档树契约、服务端静态渲染和旧数据迁移；当前功能没有结构化内容查询或协同编辑需求。未采用外部 CMS，因为它会引入额外身份、权限、部署和数据同步边界。

## 一、全局错误提示

### 错误读取

- 保留 Server 的统一错误 envelope：`code`、`message`、`data`、`meta`。
- 扩展 Admin 现有 API 响应工具，使其可以从 Axios 错误中读取 `response.data.message`，缺失时回退为“请求失败，请稍后重试”。
- 不覆盖 Axios 错误的 `response`、`status` 或 `code`，现有 404、409 等分支仍可按状态判断。

### 展示机制

- Admin 根节点挂载一个全局错误提示组件。
- 使用一个轻量模块级通知入口连接 React Query 和少量非 React Query 请求，不增加 toast 依赖。
- 通知入口只接受 `normal` 和 `session` 两种优先级；除认证生命周期明确发出的会话失效事件外，所有 API 错误均为 `normal`。
- React Query 的 `QueryCache.onError` 和 `MutationCache.onError` 只在最终失败时发送提示，避免每次重试都弹出错误。
- 登录和个人中心等直接调用 API 的事件处理器在 `catch` 中调用同一通知入口。
- 实现时盘点全部 Admin `apiClient` 调用点：React Query 管理的请求只走全局 cache 回调，直接请求显式调用通知入口，认证恢复按下述规则单独处理，避免遗漏或重复触发。
- 首次启动时，会话恢复得到的预期匿名 401 保持静默，不显示“登录状态已失效”。自动刷新成功的原请求也不显示错误。
- 已认证会话遇到无法恢复的 `AUTH_SESSION_EXPIRED` 时，认证流程清除本地令牌、切换为匿名并发送 `session` 提示；提示组件位于认证路由之外，确保跳回登录页后仍可见。主动退出登录不发送该提示。

### 单条与优先级规则

- 提示容器最多渲染一条错误。
- 第一条普通错误显示 3 秒；占用期间到达的后续普通错误直接忽略，不替换、不排队，也不延长计时。
- 当前提示关闭或 3 秒到期后，下一条新到达的普通错误才可以显示；占用期间忽略的错误不会补显。
- 只有认证生命周期已经决定使当前用户退出登录的非预期会话错误，才标记为 `session` 高优先级。该提示立即替换当前提示并重新开始 3 秒计时；不能仅凭任意 HTTP 401 推断高优先级。
- 普通错误不得覆盖会话级高优先级提示。新的会话级高优先级提示可以替换当前提示并重新计时。
- 提示使用 `role="alert"`，提供关闭按钮；手动关闭后清理计时器。
- 页面原有表单校验和带重试按钮的结构性错误状态可以保留，但不再各自生成第二条全局通知。

## 二、短信登录交互

### 默认状态

- 短信登录面板只展示手机号、短信验证码输入框和发送按钮。
- 切换到短信登录时不请求图形验证码。
- 发送按钮可用性、视觉、指针、`disabled` 属性和点击行为使用同一条件。

### 发送流程

1. 用户点击发送按钮。
2. Admin 先校验手机号；无效时显示表单校验错误，不打开弹窗。
3. Admin 打开现有 Radix Dialog，并在弹窗打开后请求图形验证码。
4. 用户输入 4 位图形验证码并确认。
5. Admin 提交手机号、`captchaId` 和图形验证码。
6. 发送成功后关闭弹窗、清空图形验证码状态，并启动发送按钮倒计时。
7. 发送失败时弹窗保持打开，清空输入并刷新图形验证码；全局提示显示 Server `message`。

### 冷却

- Server 的发送响应增加 `cooldownSeconds`，由当前 `SMS_SEND_COOLDOWN_SECONDS` 配置返回；默认值为 60。
- Admin 使用响应值启动倒计时，不另外复制后端配置。
- 按钮依次显示“60秒后重发”“59秒后重发”直到“1秒后重发”，期间保持禁用。
- 归零后按钮恢复“发送验证码”并重新可用。
- 页面卸载时清理计时器。

### 最终登录

- 最终请求继续只包含 `phone` 和 `code`。
- 图形验证码只保护短信发送操作，不进入最终登录 DTO、共享类型或服务校验。

## 三、认证防爆破

### 现有保护保持不变

- 每手机号短信发送冷却默认 60 秒。
- 每手机号每小时最多发送 5 次短信。
- 每个短信验证码最多失败 5 次，成功或耗尽后原子消费。
- 每个图形验证码最多失败 5 次，成功或耗尽后原子消费。
- 验证码只存 HMAC 摘要，不存明文。

### 密码登录限制

- 新增配置：`AUTH_PASSWORD_MAX_ATTEMPTS=5`。
- 新增配置：`AUTH_PASSWORD_WINDOW_SECONDS=900`。
- 每次密码登录在查询用户或执行密码哈希校验前，按标准化账号标识消耗一次 Redis 尝试额度。
- Redis key 使用账号标识的 HMAC 摘要，避免在 key 中保存手机号或用户名明文。
- 任意账号字符串都会进入同一流程，避免通过限流行为枚举真实管理员。
- 超限返回 HTTP 429、`RATE_LIMIT_EXCEEDED` 和安全文案“登录尝试过于频繁，请稍后重试”。
- 前 5 次尝试允许进入凭据校验，第 6 次及以后在窗口内直接拒绝；登录成功后删除该账号标识的尝试窗口，失败时保留计数直至窗口到期。
- Redis 使用单条 Lua 操作完成自增、首次设置 TTL 和上限判断，避免并发绕过或无过期计数。

### 配置与文档

- 所有值通过 `ConfigService` 读取。
- `.env.example` 和 `docs/environment-variables.md` 同步记录新增配置、默认值和作用。

## 四、课堂文章权限与状态

### RBAC

- 保留 `content.article.view` 和 `content.article.read`。
- 新增按钮权限 `content.article.write`：显示读取详情、新建和编辑草稿/已下线文章、上传文章素材的界面动作；隐含 API 权限 `content.article.write_action`。
- 新增按钮权限 `content.article.publish`：显示发布和下线动作；隐含 API 权限 `content.article.publish_action`。
- `super_admin` 继续通过现有规则自动获得目录中的全部权限。
- 其他角色必须显式获得对应动作权限；仅有查看权限不能写入或发布。

### 状态机

允许的状态转换：

```text
create -> draft
draft -> published
published -> offline
offline -> published
```

- `draft` 和 `offline` 可编辑；编辑后保持原状态。
- `published` 不可编辑，必须先下线。
- 每次发布将 `publishedAt` 更新为当前时间。
- 下线保留最后一次 `publishedAt`，但公开查询通过 `status=published` 排除文章。
- 创建者写入 `authorId`，后续编辑、发布或下线不改变作者。

### 并发

- 更新、发布和下线请求携带 `expectedUpdatedAt`。
- Server 在状态条件和 `updatedAt` 同时匹配时才更新。
- 不匹配返回 HTTP 409 和稳定错误码，提示管理员刷新后重试。
- 该方案复用现有 `updatedAt`，不新增 revision 字段。

## 五、课堂文章 API 契约

在 `@petcare/shared-types` 增加带完整 JSDoc 的以下契约：

- `AdminClassroomArticleDetail`
- `CreateAdminClassroomArticleRequest`
- `UpdateAdminClassroomArticleRequest`
- `AdminClassroomArticleStateRequest`
- `UploadAdminClassroomArticleMediaResponse`
- 富文本公开响应字段 `bodyHtml`

写入边界：

- 标题去除首尾空白后为 1 至 120 个字符；摘要去除首尾空白后为 1 至 500 个字符。
- 草稿或已下线文章允许正文为空；发布时，清洗后的正文必须至少包含非空白文本或一张有效素材图片。
- `bodyHtml` 最多 200,000 个字符、最多 50 张图片；Server 在清洗和素材校验前后都执行边界检查。
- 封面可为空；新建请求用 `coverAssetId` 选择活动素材。更新请求省略该字段表示保留当前封面，传 `null` 表示清除，传素材 ID 表示替换；不接受客户端直接提交任意 URL。
- Admin 列表和详情返回 Server 基于 `WEBSITE_PUBLIC_URL` 生成的 `publicUrl`；详情另返回 `bodyHtml` 和当前 `coverUrl`。创建、更新、发布和下线都返回最新详情，使客户端取得新的 `updatedAt`。

Admin API：

| 方法 | 路径                                   | 权限                             | 用途                 |
| ---- | -------------------------------------- | -------------------------------- | -------------------- |
| GET  | `/admin/content/articles/:id`          | `content.article.write_action`   | 读取编辑详情         |
| POST | `/admin/content/articles`              | `content.article.write_action`   | 新建草稿             |
| PUT  | `/admin/content/articles/:id`          | `content.article.write_action`   | 编辑草稿或已下线文章 |
| POST | `/admin/content/articles/:id/publish`  | `content.article.publish_action` | 发布文章             |
| POST | `/admin/content/articles/:id/offline`  | `content.article.publish_action` | 下线文章             |
| POST | `/admin/content/articles/media-assets` | `content.article.write_action`   | 上传正文或封面图片   |

列表接口继续返回摘要字段，不返回完整正文。公开接口继续只返回 `published` 状态；详情响应将原来的转义纯文本 `body` 改为清洗后的 `bodyHtml`。

Controller 必须先注册固定的 `/articles/media-assets` 路由，再注册 `/articles/:id`，避免固定路径被文章 ID 参数吞掉。

## 六、富文本与图片

### 编辑器能力

Admin 使用 Tiptap StarterKit 内置的 Link，并增加 Image 扩展。首版工具栏支持：

- 段落、二级和三级标题
- 粗体、斜体、删除线
- 有序列表、无序列表、引用
- 链接
- 撤销和重做
- 上传并插入正文图片

不支持脚本、iframe、任意样式、字体族、字号、表格、视频或外部嵌入。

### 图片上传

- 上传继续接受 JPEG、PNG 和 WebP，复用现有字节探测、10 MiB 上限、尺寸限制、校验和及腾讯 COS 存储。
- Content 模块复用 Website Content 模块已实例化的媒体服务，不复制 COS 客户端或存储配置。
- 上传响应返回素材 ID 和公开 URL。
- Tiptap 图片节点写入 `src`、`alt` 和 `data-asset-id`。
- Server 保存文章时验证每个 `data-asset-id` 对应活动素材，且 `src` 与服务端解析出的公开 URL 一致。
- 封面上传使用同一端点；保存请求传素材 ID，Server 解析并写入现有 `coverUrl`。

### 素材归档保护

- Website Media 归档检查同时覆盖课堂文章。
- 当素材公开 URL 等于任一文章 `coverUrl`，或文章正文包含对应 `data-asset-id` 时，素材不可归档。
- 草稿、已发布和已下线文章都视为有效引用，避免编辑历史中的图片失效。

### HTML 安全边界

- Admin 输出不可信；Server 保存时使用 `sanitize-html` 严格清洗，并在公开读取时再次清洗。
- 为区分历史纯文本与新富文本，Server 只把带内部精确前缀 `PETCARE_CLASSROOM_RICH_TEXT_V1\n` 的数据库值解释为 HTML；该前缀由 Server 在清洗完成后写入，不接受客户端传入，也不返回给 Admin 或 Website。
- 不带前缀的历史 `content` 永远按纯文本处理：先 HTML 转义，再按换行包装为段落。编辑历史文章时，Admin 接收转换后的安全 `bodyHtml`；保存后才变为带前缀的 v1 富文本。
- 允许标签限定为编辑器实际支持的段落、标题、强调、列表、引用、链接、图片、换行和分隔线。
- 禁止 `style`、`class`、事件属性、SVG、MathML、表单、脚本、iframe 和未知标签。
- 链接只允许 `http`、`https` 和 `mailto`；图片只允许已验证的托管素材 URL，不允许 `data:` 或任意外部图片。
- 外链统一补充安全的 `rel` 属性。
- 正文应用上述 200,000 字符和 50 张图片上限，避免超大文档消耗服务资源。
- 官网使用 Astro `set:html` 仅渲染 Server 返回的 `bodyHtml`，不直接渲染 Admin 请求内容或数据库原值。

## 七、Admin 页面

### 路由

- `/content/articles`：现有列表。
- `/content/articles/new`：新建草稿。
- `/content/articles/:id/edit`：编辑草稿或已下线文章。

详情不另建只读页面；已发布文章在列表中通过官网链接预览，编辑前需先下线。

### 列表操作

- 有写权限时显示“新建文章”。
- 草稿显示“编辑”和“发布”。
- 已发布显示“查看官网”和“下线”。
- 已下线显示“编辑”和“重新发布”。
- 发布与下线使用现有 Radix Dialog 做确认。
- 操作进行中按钮保持视觉、指针、无障碍属性和行为一致。

### 编辑表单

- 字段包括标题、摘要、封面和富文本正文。
- 保存只写草稿/已下线内容，不自动发布。
- 发布仍由列表或保存后的显式发布动作触发。
- 服务端错误通过全局单条提示展示；字段级本地校验就地显示。

## 八、官网兼容

- 已发布文章列表行为不变。
- 文章详情改为渲染 `bodyHtml`，补充富文本排版和响应式图片样式。
- 旧纯文本正文按内部格式前缀判定，并按上述规则安全转换；不能通过内容看似 HTML 就绕过转义。首次通过 Tiptap 保存后才写成 v1 富文本。
- 草稿、已下线或不存在的文章继续统一返回 404，不泄露后台状态。

## 九、错误处理

- 无效富文本、危险 URL、无效或已归档素材返回 400。
- 不存在的文章返回 404。
- 非法状态转换和并发冲突返回 409。
- 无写入或发布权限返回 403。
- COS 不可用返回现有稳定 503 存储错误。
- 所有错误沿用统一 envelope，并由 Admin 全局错误提示展示 `message`。

## 十、TDD 测试边界

以下公开 seam 已在对话中确认：

### Admin 错误提示

- Server `message` 能进入全局错误提示。
- 提示 3 秒后关闭。
- 第一条普通错误显示期间忽略后续普通错误，且不重置计时、不补显。
- 普通错误关闭或到期后，新发生的普通错误可以显示。
- 非预期会话失效并触发退出登录时，高优先级提示立即覆盖当前普通错误并重置 3 秒计时；普通错误不能反向覆盖它。
- 主动退出、首次匿名恢复及普通 401 不产生高优先级提示。
- React Query 重试中的中间失败不重复提示。
- 首次会话恢复的预期匿名 401 不提示；已认证会话失效并退出时显示高优先级提示。

### 登录

- 默认短信面板没有图形验证码。
- 发送按钮打开图形验证码弹窗，弹窗打开后才加载挑战。
- 有效挑战发送短信；失败时刷新挑战并显示 Server `message`。
- 发送成功后按钮显示 `60 -> 59 -> ... -> 0` 并保持正确禁用状态。
- 最终短信登录不提交图形验证码。
- 密码尝试达到上限后返回 429，窗口到期或登录成功后恢复。
- Redis 并发尝试不能绕过限制。

### 课堂文章

- shared-types 契约和 RBAC 父子/隐含权限关系。
- Controller 路径、权限和当前管理员传递。
- 创建、编辑、发布、下线及非法状态转换。
- `expectedUpdatedAt` 并发冲突。
- HTML 白名单清洗和危险输入拒绝/移除。
- v1 格式前缀识别与历史纯文本转义，伪装成 HTML 的旧内容不能直接渲染。
- 标题、摘要、正文长度及正文图片数量边界。
- 图片素材有效性、URL 一致性和归档引用保护。
- Admin 新建、编辑、图片上传、发布和下线交互。
- 公开接口只返回已发布文章并输出安全 `bodyHtml`。
- Website 安全渲染富文本与响应式图片。

## 十一、验证范围

按实际影响运行以下范围，不默认执行无关全仓测试：

- `@petcare/shared-types`：相关契约、RBAC 测试、类型检查。
- `@petcare/server`：Auth、Redis、Content、媒体服务和 Controller 聚焦测试；lint、类型检查和构建。
- `@petcare/admin`：API 响应、全局提示、Login、课堂文章 API/页面测试；样式门禁、lint、类型检查和生产构建。
- `@petcare/website`：文章 API、详情渲染和路由契约测试；样式门禁、类型检查和生产构建。
- `git diff --check` 检查补丁卫生。

只有聚焦测试无法覆盖真实跨应用边界，或变更暴露基础设施不确定性时，才扩展到相关 E2E；不因“完成”本身运行全仓 E2E。

## 十二、明确取舍

- 全局错误提示使用项目内最小实现，不引入通知库。
- 富文本编辑器使用成熟依赖，不手写编辑引擎。
- HTML 清洗在 Server 完成，浏览器端校验不作为安全边界。
- 复用现有媒体能力和 `content` 字段，不新增平行媒体域或文章版本系统。
- 密码防爆破按账号标识执行；可信代理边界建立前不实施可能误伤用户的 IP 限流。
