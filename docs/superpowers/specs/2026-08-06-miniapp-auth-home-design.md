# Miniapp 登录页与首页品牌化设计

## 目标

以 `D:\projects\petcare-ai` 的 H5 首页原型和用户提供的首页截图为布局基准，优先完成 Miniapp 登录页与首页的视觉和交互改造。页面保持原型的信息架构与模块顺序，统一映射到 PetCare 品牌系统，并移除这两个页面的微信原生标题栏。

## 设计依据

- H5 原型：`D:\projects\petcare-ai\src\pages\index.tsx`
- 首页截图：顶部问候、定位、轮播、进行中服务、热门悬赏、养宠课堂、社区信息流与五项底部导航

## 本次范围

## 导航策略

### 登录页

- 不显示微信原生标题栏。
- 不提供返回按钮，登录成功后统一通过 `switchTab` 进入首页。
- 内容从状态栏安全区下方开始，避免胶囊按钮和系统状态栏遮挡。

### 首页

- 不显示微信原生标题栏。
- 页面顶部直接承载问候、头像、定位与消息入口，形成沉浸式首屏。
- 保留五项自定义 TabBar，并为页面底部预留 TabBar 与安全区高度。

### 后续页面

- 本次不全局关闭原生导航，避免尚未改造的详情页失去返回能力。
- 后续一级 Tab 页面沿用沉浸式顶部。
- 后续详情、编辑等二级页面使用统一的自定义返回导航。

## 登录页设计

登录页采用“沉浸式品牌欢迎区 + 底部微信授权卡片”结构：

1. 全屏使用浅色品牌渐变和低对比度装饰层，整体保持安静、温暖和可信赖。
2. 欢迎区展示高清 PetCare Logo、品牌短句和简洁的信任说明。
3. 白色授权卡片承载页面标题、登录说明、微信手机号授权按钮、隐私提示和错误反馈。
4. 主按钮使用品牌蓝，按钮高度和触控区不小于 44px。
5. 登录中锁定按钮并显示加载状态；错误信息在按钮附近显示，页面高度保持稳定。

登录流程保持不变：

```text
微信手机号授权 -> 微信登录 -> 必要时绑定手机号 -> switchTab 进入首页
```

拒绝手机号授权、绑定令牌过期、接口业务错误和未知错误继续使用现有错误分类，不丢失当前页面状态。

## 首页设计

首页严格保持以下模块顺序：

1. 问候、用户头像、定位和消息入口
2. 品牌场景轮播
3. 进行中的服务卡片或空状态
4. 横向滚动的热门悬赏
5. 养宠小课堂列表
6. 社区精选信息流
7. 固定自定义底部导航

### 顶部信息区

- 已登录时展示用户昵称和头像；没有头像时使用昵称首字或品牌 Symbol 回退。
- 游客使用中性称呼，不制造虚假的个人信息。
- 定位暂用原型展示数据，后续接入真实定位时保持相同布局。
- 消息按钮提供未读圆点，并保持至少 44px 的触控区域。

### 品牌轮播

- 使用 Miniapp 运行时目录中的三张高清品牌场景图，不依赖外部图片域名。
- 保留自动播放、循环和分页指示器。
- 每张轮播只保留一个主要行动，按钮跳转到现有业务页面。

### 服务状态

- 登录态恢复中展示稳定的加载占位。
- 游客展示登录引导。
- 已登录且有进行中服务时，展示宠物、服务类型、预计完成时间、进度和两个后续操作。
- 已登录但无服务时，展示明确空状态和发布悬赏入口。

### 内容模块

- 热门悬赏保持横向滚动卡片布局，琥珀色只用于价格、悬赏和有限提醒。
- 养宠课堂保持带缩略图的纵向列表，并使用语义标签区分类别。
- 社区精选保持头像、作者信息、正文、媒体和互动数据的内容卡片结构。
- 首轮使用类型明确的页面原型数据，后续接入真实接口时替换数据源，不改变组件输入契约。

## 组件边界

- 页面级安全区容器只负责状态栏间距，不承载业务状态。
- 登录页保留认证编排和错误处理，视觉子区保持无业务副作用。
- 首页组件按顶部、轮播、服务状态、悬赏、课堂和社区拆分，每个组件只接收渲染所需数据和事件。
- 原型数据集中定义并带有字段说明，页面组件不重复声明共享业务类型。
- 自定义 TabBar 继续负责一级页面切换、选中态和未读提示，不与首页业务耦合。

## Tailwind 与小程序约束

- 使用 Tailwind CSS v4 CSS-first 配置和 `app.css` 的 `@theme` 语义 token。
- 自定义尺寸必须先定义 token，再使用 `h-*`、`w-*`、`pt-*` 等安全语义类。
- 禁止任意值类、分数尺寸、动态类名片段、`rem/rpx` 和页面级 CSS/SCSS。
- 只有运行时状态栏高度使用 Taro 平台信息计算，不将设备尺寸硬编码进页面。
- 所有触控目标不小于 44px，相邻触控目标保留至少 8px 间距。

## 动效与反馈

- 页面首次进入使用轻量透明度和位移动效，时长控制在 200–300ms。
- 按钮和卡片按压反馈控制在 100–200ms，不使用依赖鼠标悬浮的交互。
- 不动画修改布局高度，避免页面跳动和滚动抖动。
- 轮播和进度变化表达真实状态，不增加纯装饰性长动画。
- 用户选择减少动态效果时，页面保持可用并缩短或取消非必要动效。

## 测试与验收

- 登录页测试覆盖授权成功、手机号绑定、重复点击、拒绝授权和错误反馈。
- 首页测试覆盖游客、登录态恢复、已登录空状态和进行中服务状态。
- 页面配置测试确认登录页和首页使用自定义导航，其他未改造页面仍保留原生导航。
- 自定义 TabBar 测试覆盖五项路由、选中态、未读提示和切换行为。
- 运行 Miniapp ESLint、TypeScript 类型检查、Jest 单元测试、样式策略检查和微信生产构建。
- 检查最终 WXSS 不包含任意尺寸、`rem/rpx`、不支持的选择器或原型外部图片依赖。
- 在微信开发者工具中人工检查状态栏、胶囊区、底部安全区、横向滚动和长页面滚动体验。
