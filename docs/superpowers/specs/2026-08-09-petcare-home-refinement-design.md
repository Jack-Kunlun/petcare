# PetCare 小程序首页精修设计规格

## 状态与交付物

- 原始画板：`Home / Default`（节点 `265:3`）
- 精修画板：`Home / Default / Refinement`（节点 `296:35`）

本次在保留原始画板的前提下新增精修版本，没有覆盖已确认的设计，也没有调整现有 Figma 页面层级。

## 目标

本次工作是对已完成首页进行精修，不是重新设计。目标是在不改变产品信息架构的前提下，提升首页的整体感、信息层级、内容密度与品牌质感，使页面同时具备：

- Apple 风格的克制、清晰与秩序；
- Airbnb 风格的温暖、真实与生活感；
- 上门宠物服务所需的专业、可信与安全感。

## 非目标与保留边界

本次不改变以下内容：

- 首页模块顺序与业务结构；
- 现有业务文案、真实摄影和品牌资产；
- 首页五项底部导航目的地；
- 原有原型关系与组件实例关系；
- Figma 文件既有页面命名及层级；
- 登录页及其他业务页面。

本次不提前抽离新的公共组件。待更多页面稳定后，再依据真实复用场景沉淀组件，避免形成需要反复返工的预设抽象。

## 设计原则

1. **内容优先**：摄影、服务进度、悬赏信息和社区内容承担主要表达，装饰不抢占注意力。
2. **弱化容器感**：减少阴影和层层套卡，通过间距、浅边框和背景层级组织内容。
3. **主次明确**：Primary Blue 仅用于当前状态和关键行动；Amber 只强调价格或提醒。
4. **温暖但不幼稚**：使用真实宠物摄影、柔和暖色头像和 Care 色，不使用卡通化的大面积装饰。
5. **可实现**：所有调整基于现有语义变量、尺寸体系和可用字体，避免依赖不可落地的视觉技巧。

## 页面结构与滚动模型

页面采用固定顶部导航、纵向内容滚动区和固定底部 TabBar。精修版滚动内容高度为 `1809px`，可视区域高度为 `740px`，底部 TabBar 位于 `y=740`、高度 `72px`。

滚动内容模块顺序和尺寸如下：

| 模块            | Y 坐标 | 高度 |
| --------------- | -----: | ---: |
| Welcome & Hero  |      0 |  328 |
| My Service      |    328 |  292 |
| Hot Bounties    |    620 |  256 |
| Pet Classroom   |    876 |  380 |
| Community Picks |   1256 |  457 |

页面主水平边距为 `16px`，主要内容宽度为 `343px`。画板维持微信小程序常用的 `375px` 设计基准；`343px` 内容宽度及少量半像素居中位置属于由设备宽度推导的必要几何结果，不强行改为偶数尺寸。

## 模块精修规范

### 1. 顶部欢迎区

- 头像使用温暖的 Warning Soft 背景，展示用户姓氏，避免无意义占位图标。
- 问候语使用 `12px` 次级文本；用户名称使用 `18px` 中等字重。
- 城市与区域信息使用 `14px`，保持易读但不过度突出。
- 通知入口保留 `44×44px` 触控区域，视觉容器为 `40px`。
- 未读徽标缩小为 `12px`，数字使用 `10px`，避免压过主内容。

### 2. Hero 轮播

- 使用现有批准摄影和裁切，不重新生成图片。
- Hero 高度为 `176px`，圆角 `16px`。
- 标题使用 `22/28px`、Medium；副文案使用 `14/20px`，透明度约 `76%`。
- CTA 视觉尺寸为 `124×40px`，圆角 `20px`，保持轻量。
- 轮播指示器：当前项 `16×4px`，非当前项 `4×4px`，间距 `4px`。
- 文案、按钮和轮播控件必须保持为可编辑图层，不烧录进图片。

### 3. 我的服务

- 卡片高度由 `256px` 收紧为 `220px`，模块总高度调整为 `292px`。
- 背景使用 Brand Soft 与 Canvas 的柔和叠加，配合浅色边框，不使用阴影。
- 内边距为 `16px`，主要内容间距为 `8px`。
- 状态标签为 `72×28px` 胶囊形；服务者头像为 `44px`。
- 进度条高度为 `4px`，同时保留明确的百分比文字，状态不能只靠颜色表达。
- 两个底部操作等宽，高度均为 `44px`，主次关系通过填充与描边区分。

### 4. 热门悬赏

- 横向卡片宽度由 `284px` 调整为 `272px`，轨道宽度 `840px`，卡片间距 `12px`。
- 首屏应露出第二张卡片的一部分，明确表达横向可滑动性。
- 卡片内边距 `16px`，圆角 `16px`，使用浅边框，不使用阴影。
- 宠物图片为 `40px`；正文使用 `14/20px`。
- 价格使用 `20px` Bold，并且只在价格处使用 Amber，避免整卡高饱和。

### 5. 宠物课堂

- 模块总高度为 `380px`。
- 首篇精选内容尺寸为 `343×120px`，内边距 `16px`。
- 精选图片尺寸为 `112×88px`，圆角 `12px`；标题使用 `16/24px`。
- 其余文章保留紧凑列表形态，通过分隔线建立节奏，不额外套卡。
- “更多”操作统一使用文字与 Chevron，容器无填充、无描边、无阴影。

### 6. 社区精选

- 模块总高度为 `457px`，社区内容卡维持 `343×385px` 的信息结构。
- 头像使用温暖背景，主体图片使用真实摄影。
- 正文使用 `14/22px`，保证生活化内容的阅读舒适度。
- 卡片只使用浅边框，不使用阴影。
- “发现更多”采用与课堂一致的透明文字操作和 Chevron，形成跨模块一致性。

### 7. 底部导航

- 保留首页、悬赏、社区、消息、我的五个目的地。
- 背景为约 `98%` 不透明白色，顶部使用细分隔线，不使用悬浮阴影。
- 标签字号为 `14px`；当前项 Medium，非当前项 Regular。
- 当前项使用品牌蓝，同时通过图标线宽和文字字重辅助表达，不能只依赖颜色。
- 消息未读徽标为 `12px`，数字为 `10px`。

## 视觉系统约束

### 色彩

- 页面 Canvas：`#F8FAFC`，通过现有语义变量绑定。
- Primary Blue：用于关键行动、当前导航和服务进度。
- Care Mint：用于陪伴、服务与温暖的辅助表达。
- Amber：仅用于价格、提醒与悬赏相关重点。
- Danger Red：仅用于真实危险或失败状态，不用于点赞等普通互动。
- 卡片表面保持白色或极浅语义背景，避免通过大面积色块切割页面。

### 字体

- 中文继续使用文件中已批准且可用的 `Noto Sans SC`。
- 不为追求提示词中的 PingFang SC、HarmonyOS Sans 或 MiSans 而引入当前文件不可验证的字体依赖。
- 页面可见文本字号保持在现有移动端层级中，精修版不存在异常的奇数字号。

### 圆角、边框与阴影

- 大型媒体和主要内容卡圆角以 `16px` 为主；内部图片使用 `12px`。
- 内容卡优先使用浅边框区分层级。
- 我的服务、三张悬赏卡、精选文章和社区卡均不使用可见阴影。
- “更多”和“发现更多”等轻操作不使用按钮底板。

### 图标

- 继续使用现有线性图标体系，不使用 Emoji 代替功能图标。
- 同一层级图标保持一致的视觉重量与尺寸。
- 图标按钮的可点击区域不小于 `44×44px`。

## 交互与无障碍

- 可点击目标原则上不小于 `44×44px`。
- Hero CTA 的视觉高度为 `40px`，模块标题操作的视觉高度为 `28px`；前端实现应通过 `hitSlop` 或等效机制扩展实际触控区域到至少 `44px`，不得改变当前视觉尺寸。
- 横向悬赏列表应支持自然滑动，并保留第二张卡片露出作为可发现性提示。
- 轮播应支持手动切换、暂停以及减少动态效果偏好。
- 状态信息必须同时使用文字、图标或形状表达，不能只依赖颜色。
- 所有图片需要可用的替代文本；装饰性图片应明确标记为装饰内容。

## Figma 实施说明

- 所有调整继续使用现有语义变量、尺寸变量和组件实例。
- 未分离任何组件实例，也没有破坏主组件关系。
- Figma 渲染过程中曾出现新增变量绑定 Paint 的基础值显示为黑色的问题。处理方式为：保留变量绑定，同时将 Paint 基础值写入 Light 模式下解析后的实际颜色；这属于工具渲染兼容处理，不是新增颜色 Token。
- 本次没有新增公共组件。首页稳定并与后续页面形成真实重复后，再执行组件剥离和复用。

## 剩余风险与实现提醒

- 本次仅完成 Figma 视觉精修，尚未同步到小程序代码。
- `375/343px` 布局和少量半像素居中是设备宽度推导结果，不应在实现时机械改成偶数网格。
- Hero CTA 与轻量文字操作需要由前端补足隐形触控区域，并在真机上验证可点击性。
- 摄影裁切、系统字体渲染和安全区高度需在至少一台 iOS 与一台 Android 微信环境中复核。
- 后续页面出现稳定复用模式前，不应提前扩建组件库。
