# Admin PC 端二级侧栏导航设计

## 背景

当前 Admin 将用户管理、订单管理等模块的子页面渲染为内容区顶部的横向导航，同时共享 RBAC 目录已经通过 `parentCode` 声明了菜单层级。两套导航来源不一致，导致页面重复展示导航、菜单在左侧扁平化展示，并且后续新增菜单容易遗漏页面导航。

## 目标与范围

### 目标

- 将 PC 后台统一为“一级侧栏 + 右侧二级侧栏 + 主内容区”。
- 菜单、路由和权限均从共享 RBAC 目录与 Admin 路由注册表生成。
- 删除页面内容区顶部的模块级横向导航。
- 将 RBAC 的角色管理、菜单目录拆分为独立页面路由。
- 保证详情页、编辑页等深层路由能够高亮对应的父级菜单。

### 非目标

- 本次只改造 PC 后台，不新增或调整移动端二级菜单。
- 投诉工作队列中的状态队列按钮仍是筛选控件，不改为页面路由菜单。
- 不改变服务端权限守卫、业务接口权限或数据库表结构。

## 方案

### 1. 菜单数据流

菜单数据的唯一来源保持为：

```text
@petcare/shared-types RBAC_PERMISSION_CATALOG
  -> Admin ADMIN_ROUTE_REGISTRY
  -> 一级侧栏 / 二级侧栏
```

路由注册表提供以下能力：

- 返回当前权限可见的一级菜单；
- 返回指定一级菜单下当前权限可见的二级菜单；
- 根据当前 URL 找到所属一级菜单；
- 对动态详情、编辑路径使用 React Router 的路径匹配规则，保证父级菜单保持激活状态。

一级菜单只展示 `parentPath === null` 的路由。存在可见子路由但当前用户没有父级菜单权限时，一级菜单作为不可进入的分组标题展示，子菜单仍按自身权限过滤，避免通过展示菜单绕过服务端授权。

### 2. PC 布局

`Layout` 调整为三列结构：

```text
深色一级 Sidebar | 浅色 SecondarySidebar | 页面 Header + Main
```

- 一级侧栏保留品牌、一级菜单、系统状态和现有桌面端视觉风格；
- 二级侧栏紧邻一级侧栏右侧，仅在当前模块存在可见子菜单时渲染；
- 二级菜单使用垂直链接，包含可访问名称、当前页状态和键盘焦点样式；
- 主内容区不再为模块导航预留顶部横向 Tab 的空间；
- Header 的通知、管理员信息、退出登录能力保持不变；
- 移动端现有抽屉导航保持原样，不新增本次二级侧栏交互。

### 2.1 内容滚动约束

后台桌面布局固定在浏览器视口内，禁止主内容高度反向撑大整个页面：

- 最外层布局使用 `h-screen overflow-hidden`；
- 一级侧栏、二级侧栏和内容列使用 `min-h-0`，形成可收缩的 Flex 子项；
- Header 保持固定高度；
- `main` 使用 `min-h-0 flex-1 overflow-y-auto`，页面滚动只发生在主内容区域；
- 两个侧栏保持视口高度，侧栏内容过长时仅侧栏自身滚动，不改变主布局高度。

该约束同时适用于后续新增的二级侧栏，避免内容页过长时侧栏被页面内容撑高。

### 3. 页面与路由

用户管理和订单管理沿用现有 URL：

- `/users`：用户列表二级入口；
- `/users/certifications`：认证审核二级入口；
- `/orders`：订单列表二级入口；
- `/orders/complaints`：投诉与纠纷二级入口。

RBAC 页面拆分为：

- `/rbac`：角色管理，继续使用 `rbac.view` 权限；
- `/rbac/catalog`：菜单目录，新增共享菜单权限 `rbac.catalog.view`，该权限归属系统设置一级菜单，并自动关联 `rbac.permission.read` API 权限；
- `/rbac/new`、`/rbac/:id`、`/rbac/:id/edit`：角色创建、详情和编辑，继续要求 `rbac.view`。

`RBAC_PERMISSION_CATALOG` 增加 `rbac.catalog.view` 后，服务端种子逻辑会通过既有 upsert 流程同步该权限和超级管理员角色关联，不需要 Prisma 迁移。

### 4. 页面改造

- 删除 `UserManagementNavigation` 和 `OrderManagementNavigation` 在页面中的渲染与导入；
- 将 RBAC 原有 `roles/catalog` 页面 Tab 拆为角色列表页和只读菜单目录页；
- 保留筛选区域、按钮级 `PermissionGate`、详情返回链接和投诉队列筛选按钮；
- 菜单目录页继续只读展示服务端返回的菜单/按钮目录，不提供 API 权限编辑控件。

## 权限与安全

- Admin 侧栏只负责隐藏当前用户无权访问的入口；
- Server 的 `PermissionGuard` 仍是最终授权边界；
- 二级菜单权限必须来自共享目录，禁止在 Admin 单独硬编码未登记权限码；
- `rbac.catalog.view` 仅用于菜单目录页面入口，目录接口继续使用现有 `rbac.permission.read` 守卫；
- 新旧角色均通过服务端有效权限码过滤，数据库中不存在于共享目录的孤儿权限继续被排除。

## 验证方案

### 单元测试

- 路由注册表：所有共享菜单路径唯一、父子关系一致、RBAC 菜单目录路由存在；
- 菜单查询：根菜单和二级菜单按权限过滤、稳定排序；
- 一级侧栏：仅展示一级菜单，访问子路由时父级高亮；
- 二级侧栏：展示当前模块子菜单，动态详情/编辑路由高亮对应入口；
- 用户/订单页面：不再渲染顶部模块导航；
- RBAC：角色页、菜单目录页独立渲染，权限不足时入口和页面均不可用；
- 共享权限目录：新增菜单路径、父级和 API 关联保持一致。

## 取舍

选择双侧栏而不是在主侧栏内展开树形菜单，是因为它能保持一级模块稳定、让二级页面切换始终位于同一位置，并且可以直接复用共享目录中的父子关系。移动端不在本次范围内，避免把 PC 信息架构变更与移动端交互重构混在一起。
