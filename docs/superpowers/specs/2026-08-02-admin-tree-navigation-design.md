# Admin PC 单侧栏树形导航设计

## 决策

Admin PC 只保留一个左侧菜单栏，菜单栏以内嵌树形结构展示模块和子页面。移除右侧二级侧栏，释放内容区域横向空间；移动端继续使用现有抽屉入口，不增加独立的第二菜单栏。

## 菜单结构

```text
Sidebar
├── 运营概览
├── 用户管理
│   └── 认证审核
├── 订单管理
│   ├── 订单管理
│   └── 投诉与纠纷
├── 系统设置
└── 权限管理
    ├── 角色管理
    └── 菜单目录
```

- 菜单树由 `RBAC_PERMISSION_CATALOG` 与 `ADMIN_ROUTE_REGISTRY` 共同生成，不在 Admin 中重复硬编码权限码。
- 一级节点使用模块菜单权限；二级节点使用共享目录中声明的父子关系。
- 当一级节点存在子菜单时，一级节点作为展开/收起分组；一级路由自身作为第一个实际子菜单展示，因此订单管理下同时有“订单管理”和“投诉与纠纷”两个子菜单。
- 当前 URL 所属的一级节点自动展开，详情、编辑和历史路由保持父级菜单高亮。
- 用户可通过独立的展开按钮折叠或展开有子项的一级节点。
- 父级菜单使用浅色高亮，当前实际子菜单使用深色高亮，区分导航层级和当前页面。
- 没有父级菜单权限时，不展示其子菜单，服务端权限守卫仍是最终安全边界。

## 布局与滚动

- 外层布局使用 `h-screen min-h-0 overflow-hidden`。
- 单侧栏使用 `h-screen min-h-0`，导航内容在侧栏内部滚动。
- Header 保持固定高度，`main` 使用 `min-h-0 flex-1 overflow-y-auto`，页面内容只在内容区域滚动。
- 移动端抽屉沿用现有打开、关闭和遮罩交互。

## 可访问性

- 菜单使用唯一的 `nav` 和清晰的 `aria-label`。
- 有子菜单的一级节点提供 `aria-expanded`、`aria-controls` 和独立的键盘可聚焦展开按钮。
- 当前路由由 `NavLink` 设置 `aria-current="page"`，所有链接保留可见焦点样式。
