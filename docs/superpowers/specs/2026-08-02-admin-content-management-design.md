# 后台内容管理设计

## 目标

在 Admin 中增加“内容管理”一级菜单，并提供三个稳定的二级入口：

1. 悬赏管理
2. 帖子管理
3. 课堂文章管理

本阶段先打通菜单、RBAC、路由和分页列表查询，保证页面不会出现“菜单可见但接口未授权”的半闭环状态。编辑、审核、发布等按钮动作在列表闭环稳定后再逐项增加。

## 菜单与路由

内容管理使用 `/content` 作为一级菜单的根路由，同时承载默认的悬赏管理页面。这样树形导航只展示三个二级菜单，不增加额外的“内容总览”入口：

| 层级 | 标识         | 路径                | 页面             | 权限                   |
| ---- | ------------ | ------------------- | ---------------- | ---------------------- |
| 一级 | 内容管理     | `/content`          | 内容管理父节点   | `content.view`         |
| 二级 | 悬赏管理     | `/content`          | 悬赏订单分页列表 | `content.view`         |
| 二级 | 帖子管理     | `/content/posts`    | 社区帖子分页列表 | `content.post.view`    |
| 二级 | 课堂文章管理 | `/content/articles` | 课堂文章分页列表 | `content.article.view` |

`content.view` 的共享目录标签保持“内容管理”，Admin 路由元数据将其子菜单展示标签覆盖为“悬赏管理”。现有 Sidebar 的父级浅色高亮、子级深色高亮和自动展开逻辑继续复用，不改变订单、权限管理、系统设置的现有层级。

## RBAC 与接口权限

共享权限目录增加三个菜单权限：

- `content.view`：访问内容管理和悬赏列表，并隐含悬赏列表查询 API 权限。
- `content.post.view`：访问帖子列表，并隐含帖子列表查询 API 权限。
- `content.article.view`：访问课堂文章列表，并隐含课堂文章列表查询 API 权限。

接口统一使用 `/admin/content/*` 前缀，并分别由 `content.reward.read`、`content.post.read`、`content.article.read` 保护。菜单权限只负责页面可见性，接口权限由服务端 `PermissionGuard` 强制校验。

## 后端数据与查询

### 悬赏

复用现有 `Order`、`OrderReward` 及关联用户、宠物数据，服务端固定 `orderType=reward`，不依赖用户是否拥有订单管理菜单权限。返回值沿用统一分页格式 `list/total/page/pageSize`，金额以元返回，时间使用 ISO 8601。

### 帖子

复用现有 `Post` 模型，支持关键词（帖子 ID、作者手机号、昵称、正文）和状态筛选（已发布、草稿、已删除）。列表只返回管理页面需要的摘要字段，正文不在列表中完整回传。

### 课堂文章

新增 `ClassroomArticle` 模型，字段包括标题、摘要、封面地址、正文、状态、作者、发布时间、创建时间和更新时间。首版只开放分页读取，文章编辑、发布和下线动作作为后续按钮权限扩展。

所有查询使用 DTO 做分页、长度和枚举校验；不存在的筛选值返回标准 400，数据库异常由统一 HTTP 异常日志处理。

## Admin 页面

三个页面保持现有管理台的密度与视觉规则：顶部标题和总数、筛选卡片、分页表格、加载骨架、错误重试和空状态。请求类型与响应类型全部放入 `@petcare/shared-types`，Admin API 调用集中在 `apps/admin/src/api/content/`。

- 悬赏管理：关键词、服务类型、履约状态、创建时间；展示悬赏金额、发布人、宠物、服务时间和订单状态。
- 帖子管理：关键词、状态；展示作者、正文摘要、媒体数量、互动数据和发布时间。
- 课堂文章管理：关键词、状态；展示标题、摘要、封面、作者、发布时间和更新时间。

页面默认字号和布局遵循现有 Admin Tailwind v4 规范，不新增独立 SCSS。

## 测试与验收

- shared-types：校验三个菜单权限的父子关系、路径、类型和隐含 API 权限。
- server：DTO 枚举校验、内容服务分页查询、权限装饰器和 Swagger 返回类型测试。
- admin：路由注册、菜单树可见性、三个页面的 loading/error/empty/success 状态测试。
- 验证命令：Admin Vitest、shared-types 类型检查、Server 构建、Admin Vite 构建、样式策略检查和 `git diff --check`。

## 非目标

本阶段不引入富文本编辑器、媒体上传、审核工作流或批量操作；这些能力在列表查询和权限链路稳定后，以独立按钮权限和接口逐项迭代。
