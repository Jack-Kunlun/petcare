# 后台系统设置首期设计规格

> 日期：2026-08-01
> 状态：已完成交互确认，待实施计划
> 范围：SOP 配置、评分阈值、费率设置

## 1. 背景与目标

后台当前只有 `/settings` 占位页。PRD 将 SOP 配置、评分阈值和费率设置列为系统设置核心能力；技术菜单还包含通知模板与基础数据，但两者不进入首期。

首期目标是提供安全、可审计、可回滚的配置发布能力，并确保配置变更只影响新业务实例，不改变历史订单的执行与计费结果。

## 2. 已确认的产品决策

- 首期只实现 SOP 配置、评分阈值和费率设置。
- 使用“草稿 + 立即发布”机制，不实现定时发布。
- 发布前展示差异并二次确认。
- 已创建订单使用创建时配置快照，新订单使用当前发布版本。
- 历史恢复通过“复制为新草稿，再重新发布”完成，不直接激活旧版本。
- 编辑者与发布者可以是同一人，首期不实现双人审批。
- 所有配置变更均记录操作者、版本、时间和变更摘要。
- 通知模板、服务类型、宠物品种与地区管理分别进入后续规格。

## 3. 架构选择

采用“领域配置模块 + 共享发布内核”。

### 3.1 共享发布内核

发布内核只处理与具体业务无关的生命周期：

- 配置键和领域类型；
- 版本号及 `draft`、`published`、`superseded` 状态；
- 当前发布版本指针；
- 草稿创建人、更新人、发布人和时间；
- 来源版本，用于从历史版本创建草稿；
- 乐观并发版本；
- 幂等发布请求；
- 变更摘要与审计事件。

每个配置键最多存在一个草稿和一个当前发布版本。发布必须在单个数据库事务中完成：校验草稿、归档旧版本、发布新版本、更新当前指针并写审计记录。

### 3.2 领域模块

SOP、评分阈值和费率分别维护强类型模型与业务校验，不使用接收任意 JSON 的通用 Key-Value 配置表。

共享发布服务通过明确的领域适配接口调用各模块：读取草稿、校验、计算差异、复制历史版本和执行发布副作用。发布内核不解释领域字段。

## 4. 数据模型

### 4.1 配置版本元数据

配置版本元数据至少包含：

- 唯一标识；
- 配置键，例如 `sop:feeding`、`rating_threshold`、`fee`；
- 递增业务版本号；
- 生命周期状态；
- 乐观并发版本；
- 来源版本标识；
- 创建人、更新人和发布人；
- 创建、更新和发布时间；
- 发布幂等键；
- 变更摘要。

数据库约束保证同一配置键只有一个草稿，并通过当前版本指针或等价约束确定唯一生效版本。

### 4.2 SOP 配置

每个服务类型拥有独立模板。首期服务类型沿用订单领域已有业务值，不在系统设置中新增或删除服务类型。

每个模板固定包含 5 个有序步骤。步骤字段包括：

- 步骤序号；
- 名称；
- 操作说明；
- 预计时长，单位为分钟；
- 最少照片数量；
- 是否要求视频；
- 一个或多个违规规则。

违规规则字段包括等级、名称、说明和建议处理方式。等级为提醒、警告、严重。规则只提供结构化处理依据，不自动扣款或调整信用分；实际处罚仍由订单或纠纷流程确认。

### 4.3 评分阈值

评分配置包含：

- 最近评价统计窗口，默认 30；
- 最少有效样本数，默认 5；
- 警告阈值，默认 3.50 星；
- 暂停接单阈值，默认 3.00 星；
- 重新培训要求说明。

评分使用整数百分值存储，例如 `350` 表示 3.50 星，禁止使用 `Float`。

### 4.4 费率配置

费率配置包含：

- 平台抽成万分比，默认 `1000`，即 10%；
- 悬赏订单固定服务费，默认 `200` 分；
- 提现手续费万分比，默认 `100`，即 1%；
- 最低提现手续费，默认 `100` 分。

比例使用万分比整数，金额使用整数分，禁止使用 `Float`。

### 4.5 订单快照

订单创建时必须记录所使用的配置版本：

- SOP 步骤复制为订单不可变执行快照；
- 费率版本、计算输入和最终各项金额写入订单计费快照；
- 评分阈值不写入订单，只用于服务者资格评估。

后续发布不得重算历史订单，不得覆盖已经生成的 SOP 执行内容。

## 5. 领域行为

### 5.1 草稿

- 没有草稿时，从当前发布版本创建草稿；首次配置则从种子默认值创建。
- 保存草稿必须携带乐观并发版本。
- 保存只更新草稿，不产生业务生效副作用。
- 历史版本恢复会复制完整领域数据并创建新草稿。

### 5.2 发布

- 发布前服务端重新执行全部领域校验。
- 发布请求携带草稿版本和唯一幂等键。
- 发布成功后旧发布版本变为 `superseded`，草稿变为 `published`。
- 发布立即生效，只供发布后的新业务实例读取。
- 任一步失败必须回滚整个发布事务。

### 5.3 评分资格评估

- 使用最近 30 个已评价订单的综合评分，窗口值由当前发布配置决定。
- 少于 5 个有效评价时只展示评分，不触发自动限制。
- 低于警告阈值时生成管理员待办并通知服务者。
- 低于暂停阈值时暂停接单资格。
- 服务者完成重新培训并经管理员审核后恢复资格。

评分配置发布后影响下一次资格评估，不回写历史评价。

## 6. API 与共享契约

Admin API 按领域拆分：

- `/admin/system-settings/sop/:serviceType`
- `/admin/system-settings/rating-threshold`
- `/admin/system-settings/fee`

每个领域提供：

- 获取当前发布版本；
- 获取当前草稿；
- 创建或更新草稿；
- 分页查询版本历史；
- 获取草稿与当前版本差异；
- 发布草稿；
- 从指定历史版本复制新草稿。

另提供系统设置概览接口，返回三个领域的当前版本、草稿状态、最后发布时间和待处理提示。

请求、响应、业务值和分页契约统一定义在 `@petcare/shared-types`。列表响应只使用 `list`、`total`、`page`、`pageSize`。Admin API 文件统一放在 `apps/admin/src/api/system-settings/` 并按领域拆分。

## 7. 权限模型

- `system.view`：查看概览、当前配置和历史版本；
- `system.sop_config`：编辑 SOP 草稿；
- `system.threshold_config`：编辑评分阈值草稿；
- `system.fee_config`：编辑费率草稿；
- `system.publish`：发布草稿和从历史版本创建恢复草稿；
- `super_admin`：拥有全部权限。

接口依据 permission code 授权，不绑定固定角色名。种子数据补齐 `system.fee_config` 和 `system.publish`，默认超级管理员拥有全部新增权限。

## 8. Admin 信息架构与交互

采用已确认的 A 方案“配置控制台”：

1. `/settings` 显示三个配置领域的当前发布版本、草稿状态、最后发布信息和待处理事项。
2. 页面内使用 SOP、评分阈值和费率领域标签查看摘要。
3. 进入领域页后编辑草稿；SOP 再按服务类型切换。
4. 发布前展示当前版本与草稿的字段级差异，以及对新订单或资格评估的影响说明。
5. 发布必须二次确认，提交期间禁用重复操作。
6. 版本历史页允许查看版本详情和“复制为新草稿”。

页面目录遵循项目规范：模块目录以 `index.tsx` 为默认页，领域编辑页使用 `Edit.tsx`，版本详情使用 `Detail.tsx`。样式使用 Tailwind CSS v4 静态工具类和项目 px 主题 token，只有 Tailwind 无法合理表达时才使用 SCSS。

## 9. 校验规则

### 9.1 SOP

- 必须恰好包含 5 步，序号从 1 到 5 且唯一连续；
- 名称长度 2–30；
- 操作说明长度 10–500；
- 单步预计时长 1–240 分钟；
- 最少照片数 0–20；
- 视频要求为布尔值；
- 违规规则必须包含合法等级、名称、说明和建议处理方式；
- 发布时检查步骤完整性、重复内容和总时长。

### 9.2 评分阈值

- 统计窗口范围 5–100；
- 最少样本数不得大于统计窗口；
- 阈值范围 1.00–5.00 星；
- 暂停阈值必须严格低于警告阈值；
- 重新培训要求不能为空。

### 9.3 费率

- 平台抽成范围 0–5000 万分比；
- 提现手续费范围 0–1000 万分比；
- 固定服务费和最低手续费必须为非负整数分；
- 运行时提现手续费不得超过提现金额；
- 客户端校验只用于交互反馈，服务端必须重复执行全部校验。

## 10. 并发、错误与恢复

核心错误码：

- `SYSTEM_CONFIG_VERSION_CONFLICT`；
- `SYSTEM_CONFIG_DRAFT_EXISTS`；
- `SYSTEM_CONFIG_NOT_FOUND`；
- `SYSTEM_CONFIG_VALIDATION_FAILED`；
- `SYSTEM_CONFIG_ACTION_NOT_ALLOWED`。

处理规则：

- HTTP 409 时关闭陈旧确认状态，提示配置已变化，刷新服务端草稿并展示差异；
- 保存失败时保留页面本地输入，允许管理员重试或复制内容；
- 发布成功后失效概览、当前配置、草稿和历史版本缓存；
- 发布失败不显示成功状态，不改变当前发布版本；
- 已发布历史不可删除，只能查看或复制为新草稿。

## 11. 审计与可观测性

审计事件至少记录：

- 草稿创建与更新；
- 发布成功与失败；
- 从历史版本创建草稿；
- 配置键、来源版本、目标版本；
- 操作者、时间、请求幂等键；
- 结构化变更摘要。

日志正文遵循现有环境与脱敏策略。配置值中如果未来出现密钥或第三方凭据，不进入当前普通配置模型，必须使用独立密钥管理方案。

## 12. 测试与验收

### 12.1 Shared Types

- 请求、响应、业务常量和分页契约；
- 所有字段与业务值具有中文 JSDoc；
- 比例和金额保持整数类型。

### 12.2 Server

- 三个领域的有效与无效边界；
- 每个配置键唯一草稿和唯一当前版本；
- 乐观并发冲突；
- 发布幂等与事务回滚；
- permission code 授权；
- 历史版本复制；
- 新订单快照及历史订单不变；
- 评分资格评估的窗口、最少样本和阈值边界；
- 每次状态变更产生审计事件。

### 12.3 Admin

- 概览、领域标签和待处理状态；
- 草稿编辑与字段错误；
- SOP 五步顺序和服务类型切换；
- 差异预览和影响说明；
- 发布二次确认与重复提交禁用；
- HTTP 409 恢复；
- 历史版本复制为草稿；
- 路由权限与无障碍键盘操作。

### 12.4 E2E

至少覆盖：

1. 编辑并发布 SOP 草稿；
2. 创建新订单并获得新 SOP 快照；
3. 确认旧订单保持旧快照；
4. 发布费率并验证新订单计费快照；
5. 从历史版本创建草稿并重新发布；
6. 使用陈旧版本发布时收到冲突并恢复页面。

完成标准为相关测试、全仓 lint、typecheck、test、build、`lint:styles` 和产物样式检查全部通过。

## 13. 初始数据

首次 schema 初始化时创建：

- 每个现有服务类型的 5 步 SOP 默认发布版本；
- 评分阈值默认发布版本：窗口 30、最少样本 5、警告 3.50、暂停 3.00；
- 费率默认发布版本：平台抽成 10%、悬赏服务费 200 分、提现手续费 1%、最低手续费 100 分；
- 新增权限点并授予默认超级管理员角色。

项目仍处于早期建表阶段，不创建 Prisma migration；实施完成后仅对明确确认的本地开发数据库执行 schema reset 和 seed。

## 14. 非目标

首期不实现：

- 定时发布和未来生效日历；
- 双人审批；
- 通知模板管理；
- 服务类型、宠物品种和地区管理；
- 自动财务或信用处罚；
- 密钥、AppSecret 或第三方凭据管理；
- 任意 JSON Key-Value 配置入口。
