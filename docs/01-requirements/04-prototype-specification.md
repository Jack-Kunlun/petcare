### 通用组件规范

- **圆角：** 卡片12px，按钮8px，头像圆形
- **阴影：** 卡片 `0 2px 8px rgba(0,0,0,0.08)`
- **间距：** 页面padding 16px，列表项间距12px
- **字体：** 标题加粗16-18px，正文14px，辅助12px
- **点击反馈：** 透明度0.9或缩放0.98

产品辅助色：`#5BC8AF`（陪伴、完成、成长与温和辅助）；强调色：`#F6B343`（价格、悬赏和有限度提示）；边框：`#E6EAF0`。

### 主导航与登录跳转约定（v45）

小程序只保留以下 5 个主 Tab，其他页面均作为无底部导航栏的子页面：

~~原表头：Taro 页面路径~~

| 主 Tab   | 业务路由     | UniApp 页面路径         |
| -------- | ------------ | ----------------------- |
| 首页     | `/`          | `pages/index/index`     |
| 悬赏大厅 | `/bounty`    | `pages/bounty/index`    |
| 社区     | `/community` | `pages/community/index` |
| 消息     | `/messages`  | `pages/messages/index`  |
| 我的     | `/profile`   | `pages/profile/index`   |

**路由兼容约定：**

- `/` 是当前首页的唯一规范路由；文档早期使用的 `/home` 仅作为兼容别名，不新增独立首页页面。
- `/bounty` 是悬赏大厅的唯一规范路由；`/rewards` 及 `/rewards/publish/*` 仅保留重定向兼容，不作为新的页面目录。
- 主 Tab 使用 `switchTab` 切换，子页面使用 `navigateTo` 进入；子页面不得显示底部 Tab 栏。

**登录成功跳转约定：**

- 未登录用户访问需要身份的页面时，统一进入 `pages/auth/index`。
- 登录页的“微信登录”按钮直接使用小程序 `openType="getPhoneNumber"`；回调拿到手机号 code 后立即完成微信登录与首次绑定，不再显示第二个“授权手机号并登录”按钮。
- 微信登录或手机号绑定成功后，统一使用 `switchTab` 跳转到 `pages/index/index`，避免 `navigateBack` 返回到未登录页面或重复登录页。
- 登录页只负责认证和错误提示，不承载业务页面内容；登录态恢复由全局认证上下文负责。
- 后续增加深链跳转时，必须对目标路由做白名单校验，禁止直接使用未校验的外部 URL。

**自定义 TabBar 约定：**

- ~~Taro `tabBar.custom` 开启，组件位于 `apps/miniapp/src/custom-tab-bar`；所有 5 个主 Tab 页面声明 `usingComponents: {}`。~~
- 主 Tab 在 UniApp `pages.json` 中统一声明，后续实现使用 UniApp 原生导航能力。
- 每个 Tab 项同时展示原生图标和文字：图标 24px，文字 15px，选中态使用品牌蓝，未选中态使用辅助灰。
- Tab 切换只调用 `switchTab`，不通过 `navigateTo` 叠加页面栈；页面代码不启用懒加载，避免首次切换出现明显等待。

| ------------ | ------------------------------------------------------------------------------------------------------------------------ |

#### 9.3.5 详情页通用交互

- 页面使用 `375×812` Viewport，长内容支持 Vertical Scroll。
- Navigation Header 固定；有底部操作栏的页面固定底部操作栏，并为滚动内容保留底部安全间距。
- Back 使用返回栈，支持从收藏和关注等多个来源进入，不强制跳转到错误的固定来源。
- Loading 保留 Header 与布局骨架；Error/Unavailable 必须提供文字原因和恢复或返回路径。
- Follow/Favorite、卡片主体、电话、地图、消息和预约为独立点击区域，不允许事件串联。

## 🛠️ 小程序实现状态

- 原 Taro 实现已弃用并删除；现有页面和认证能力不视为已迁移。
- 当前 UniApp 实现位于 `apps/miniapp`，主包与分包已覆盖本原型的主要页面和路由。
- 已接入真实接口的能力包括：微信会话、个人资料、手机号绑定、头像、账户注销，以及帮助、联系、隐私和服务协议内容。
- 宠物档案仍使用本地 fixture；悬赏发布、地图、订单、SOP 监控和聊天页面明确处于静态预览状态。
- 社区、消息、收藏、关注、评价、钱包和优惠券等页面尚未形成完整业务闭环。
- Server 已有悬赏订单创建、列表和详情接口，但 Miniapp 发布与订单页面尚未完成端到端接入。
- 页面存在不代表功能交付；真实数据、权限、加载/空/错误状态和关键测试均通过后才可标记完成。
- 当前开发顺序与周期统一参见 [当前状态与开发路线图](./05-development-roadmap.md)，本原型继续作为视觉与交互验收基准。
